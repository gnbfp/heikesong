# 设计契约 v6：命运之门（首页 / 规则修正 / 剧情）—— 2026-10-25

> 本契约由 Lead 冻结，A/B/C 三个工作流共同遵守。只增不改：动手前先读本文件；接口不在此节的，不要自行发明。
> 与 v5 冲突处以本文件为准。

## 0. 用户本轮需求（原文要点）

1. 质疑旁白后**必须给提示**（现在有时不给，是漏洞）。
2. 金币在结算后**要保存**，且**要有用处**。
3. **新增首页**：能用金币换奖励（如升级），并增加难度、提升可玩性。
4. 主持人开的门**必须是「空门」**（只用来排除一个错误选项）。开陷阱会让玩家混乱。
5. 名字「三扇门」≠ 实际 6 扇门 → 改名 **「命运之门」**。
6. 点「换门」时**必须弹出重新选门的 UI**，不能自动换。
7. 决策阶段按钮**没有高亮引导**，玩家不知道该点哪。
8. 加入**剧情**：主人公为活命参加游戏，输掉会丧命（游戏失败）。

## 1. 硬约束（不变）

- 零构建：`index.html` 双击即玩；经典 script；不引外链/不引包；`file://` 可用。
- 资源只走 `Game._apply`；`game.js` 不直接加减资源。
- 状态机十字段不变（IDLE/ROUND_INTRO/NARRATOR/PICK/HOST_OPEN/DECIDE/REVEAL/SETTLE_ROUND/CASHOUT/GAME_OVER）；换门选门是 DECIDE 内的子流程（`state.flags.switchPick`），不新增状态。
- 存档键全部 `three_doors_*_v1`；读档失败静默降级、不白屏。
- ES5 风格（var/function/try-catch），不用箭头函数/let/模板串。
- 改 `data/*.json` 必须 `node tools/build-data.js` 重建 `js/data.js` 并过 `--check`。
- 不跑 git；不删测试；测试只增不删（过期断言可以改判据，但要保留检查点）。

## 2. 引擎接口（Lead 负责实现，UI/测试只消费）

### 2.1 主持人开奖池（严格「只开空门」）
- 发牌不变量：每局**至少 2 扇 `kind === 'no-prize'`（空门）**；恰好 ≤1 扇 `big_prize`。
  - 3 门：`big_prize + empty + empty`（3 门不再出小奖；小奖从 4 门起出现）。
  - 4–6 门：`big_prize + ≥2 empty + 其余按权重池`。
- `Game.hostPick(state)` **只从 `no-prize` 且未被玩家选中的门里挑**（RNG 均匀）。剧本给的 `hostOpensSlot` 也必须满足「空门 + 非玩家所选」，否则 `hostScriptFallback=true` 并改用 hostPick。
- 主持人开门展示文案固定：「主持人打开了一扇空门」。

### 2.2 质疑必给提示
- `Game.challenge(slot)` 成功后**一定**产出 `state.lastHint = { text, truthful, slot }`；
  - 优先用 `Narrator.claimFor()` 生成具体提示（哪扇门、什么门）。
  - 拿不到 claim 时兜底：`'旁白这次说的是真话/假话——信不信由你。'`（truthful 按实际判定）。
- UI 必须在质疑结果区（结算面板 / 提示条）**显示 lastHint 文本**，不能只闪 toast。
- `Game.hintText()` 返回当前 `lastHint.text || ''`。

### 2.3 换门 = 重新选门弹层
- `Game.beginSwitch()`：仅 DECIDE 且未换过门时可用；返回 `{ ok, candidates:[slot...], cost }`；置 `state.flags.switchPick = true`，发 `ui.openModal({ kind:'switch', title:'换到哪扇门？', body, actions:[{slot}] })`。
- `Game.chooseSwitch(slot)`：校验 slot ∈ candidates；扣费（换门券优先，否则 `config.economy.switchCost` 金币，可用升级折扣）；执行换门 → `reveal()`；`flags.switchPick=false`。
- `Game.cancelSwitch()`：只关弹层，回 DECIDE。
- action：`{type:'decide', choice:'switch'}` → beginSwitch；`{type:'choose_switch', slot}`；`{type:'cancel_switch'}`。
- 兼容：`decide('switch')` 不再自动换门；旧测试的自动换门断言按新流程改写。

### 2.4 首页 / 钱包 / 升级 / 难度
- 存档：`wallet` 数字，键 `three_doors_wallet_v1`；`upgrades` 对象 `{id:level}`，键 `three_doors_upgrades_v1`。
- `CodexStore` 新增：`loadWallet/saveWallet/clearWallet`、`loadUpgrades/saveUpgrades/clearUpgrades`（白名单过滤，未知 id 丢弃）。
- 引擎：
  - `Game.wallet()` / `Game.saveWallet(n)` / `Game.spendWallet(n)`（不足返回 false，不改档）。
  - `Game.setDifficulty('normal'|'hard'|'hell')`；`Game.difficulty()`。
  - `Game.upgrades()` → `[{id,name,desc,cost,maxLevel,level,effect}]`；`Game.buyUpgrade(id)` → `{ok, reason}`。
  - 结算/死亡时 `Game.saveWallet(state.coins)` 把**本局最终金币**存入钱包（幂等：同一局只存一次，用 `state.walletSaved` 标记）。
- 难度表（`data/config.json` 的 `difficulty`，数据层实现）：
  - normal：`lieBase 0.35`、耐心 3、金币 100、怀疑 2、奖励倍率 1；
  - hard：`lieBase 0.5`、耐心 2、金币 80、怀疑 1、奖励倍率 1.5；
  - hell：`lieBase 0.65`、耐心 1、金币 60、怀疑 0、奖励倍率 2。
  - 叠加：升级项的 `effect` 一律在难度初值上**加成**。
- 升级表（`data/upgrades.json`，数据层实现，≥6 条）：id/name/desc/cost/maxLevel/effect。
  - `starting_coins`（初始金币 +50/级）、`starting_suspicion`（怀疑值 +1/级）、`starting_patience`（耐心 +1/级）、`shop_discount`（商店与换门费用 −10%/级）、`peek_plus`（免费窥视次数 +1/级）、`death_insurance`（每局一次免死：耐心归零时改为金币清零并继续，maxLevel 1）。

### 2.5 剧情与死亡
- 首页剧情文案（`data/config.json` 的 `story`）：3 段，`<p>` 拼接后显示。
- 死亡：耐心归零 → `GAME_OVER` 弹层标题 **「你死了」**，正文说明「你没能撑过去……」，并显示最终金币/轮次；按钮「用金币继续（升级商店）」「重新挑战」。
- 收手/达标：`CASHOUT` 标题「活下来了」，正文含「带着金币离开」。
- 结局表新增 `death` 结局（数据层实现，`endings` 增一条 priority 最高、`lineKind:'death'`）。

## 5. 测试层（qa-verify）交付物

`tests/` 全面对齐新契约（保留旧检查点、改判据）：
1. 主持人池：1000 次发牌样本中主持人开门 100% 为 `kind==='no-prize'` 且非玩家所选；3 门发牌必含 2 空门。
2. 质疑：任意轮质疑后 `state.lastHint.text` 非空且含「门」或「真/假」；UI 显示断言。
3. 换门：`decide('switch')` 后 phase 仍 DECIDE 且 `flags.switchPick=true`、候选 ≥1；`chooseSwitch` 后 phase=REVEAL 且换了门；候选外的 slot 被拒。
4. 钱包/升级：结算后 wallet 增加；`buyUpgrade` 扣钱、等级上限、重启后读回；难度初值生效。
5. 标题/首页：`<title>` 含「命运之门」；#boot 含难度三选一与金币余额。
6. 变异样本扩充 ≥2 条（改 hostPick 允许非空门 → 必红；删 lastHint 兜底 → 必红）。
7. `run-all.js` 全绿；更新 README 里的套件数与基线（Lead 负责最终数字）。
