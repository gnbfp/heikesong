# 《三扇门：别信旁白》功能扩展与改进评审

生成时间：2026-10-25（Lead）｜评审对象：仓库 `gnbfp/heikesong`（HEAD `3cef1e0`，8 套件 514 PASS / 0 FAIL / 9 SKIP）

---

## 0. 一句话结论

**"能玩、能演、能被相信"已经达标；下一阶段要从"一个完成度高的段落"升级为"一套有长线目标、有变化、有传播性、且被自动化守着"的产品。**
最大的三个缺口不是画面，而是：**① 每轮流程恒定（没有随机事件层）② 金币后期没有出口（经济不闭环）③ 视觉/动画/性能没有任何自动化验证（真浏览器 E2E 缺失）**。

## 2. 已具备、但没打透的（按收益排序）

### 2.1 概率与随机性：只"可复现"，不"可感知"
现状：每轮 3–6 门 + 权重抽牌，但**玩家看不到概率、也没有"这一轮不一样"的体验差异**。
影响：玩 10 局与玩 1 局的新鲜感几乎相同；"专业游戏级"的重复可玩性来自**变化层**，不是来自更多牌面。
建议：加"每轮随机事件"（见 §3.1）+ 局内透明度（显示本轮坏门概率区间与旁白撒谎率区间，不剧透具体门）。

### 2.2 金币出口不足：经济在 300 金币后"死掉"
现状：6 件商品里 5 件限购 2–3 件，买空后金币不再有用途；轮次无上限，金币只增不减。
影响：中后期决策退化为"无脑加倍/收手"，`见好就收大师`（≥200 金 + ≥4 轮）几乎白送。
建议：① 无限量消耗口（押注 / 保险 / 存款利息）② 商店加"回收/合成" ③ 硬核模式设轮次上限，让金币变成"风险预算"。

### 2.3 结局与成就：可达，但缺乏呈现与引导
现状：8 结局靠优先级判定、10 成就靠全局计数；**玩家在局中看不到"离成就/结局还差什么"**。
影响：长线目标不可见 = 不存在。
建议：结算卡显示"本局新增成就 / 图鉴进度 / 结局收集 x/8"，并在设置页加"档案"入口（统计已有数据 `Game.stats()`，缺 UI 出口）。

### 2.4 演示模式：强，但只服务"上台"
现状：`?rehearsal=1` 提词器 + 固定种子，非常专业；但演示与普通体验是两套随机源（剧本 seed vs 时间 seed）。
影响：评委若连玩两局，第二局体验与彩排脚本不同，容易"演示一套、上手一套"。
建议：把"导演脚本"升级为正式机制：演示 = 固定 seed + 提词器；再提供"挑战模式（无提词器、同 seed 可分享）"给评委复现。

### 2.5 真实浏览器验证缺位（最大的工程债）
现状：`tests/` 全部跑在 Node 垫片上，无头 Edge 在本环境被沙箱挡住 → 9 条 SKIP；**视觉布局、动画、音频、真实事件语义没有任何自动断言**（本轮 3 处 UI 偏差就是这样漏到很晚才被抓到）。
影响：任何 UI 改动都可能"测试全绿但页面坏了"。
建议：① 把已验证的 20 条无头 E2E 作为"用户本机脚本"固化（`tests/e2e/`，用 Playwright）② 性能预算脚本（首屏 <1s、动画 60fps、包体 <1MB）③ 关键视觉断言（六档视口无滚动条）可在 CI 里跑。

## 3. 完全缺失的高价值层

### 3.1 随机事件层（最高优先级）
每轮开始时 12% 概率触发一个事件，效果可复现、有明确文案：`停电（本轮旁白看不清，撒谎率-10%）`、`炸弹潮（本轮炸弹权重+30%）`、`税收（金币-10%）`、`观众喝彩（本轮收益+50%但暴露门位）`、`幸运币（随机+15金）` 等 8 种。
价值：**用一层数据就改变"每局都一样"的观感**，且完全可测试（概率分布断言）。

### 3.2 长局目标与难度曲线
轮次无上限 → 加"通关"概念：第 8 轮"逃出剧场"= 通关，通关额外结算；或"硬核模式：10 轮上限 + 每轮难度递增（坏门权重↑）"。让"见好就收"与"冲到底"形成真实取舍。

### 3.3 传播性
结算卡生成"文字战报"（结局/轮次/金币/种子），一键复制——自带传播，且不需要服务器。

### 3.4 声音与氛围
已有合成音效，缺 BGM（拍频/环境垫音）与"旁白情绪音"；加 `AudioContext` 低频 pad + 事件音即可，不需要音频文件。

### 3.5 联网能力（明确不做）
排行榜/账号/皮肤商城需要后端与审核，黑客松 ROI 低，且破坏"全本地、断网可跑"的 P0。

## 4. 工程与性能改进

1. **测试分层**：单元（现有）→ 契约（现有）→ E2E（缺）→ 性能（缺）。建议新增 `tests/e2e/` 与 `tests/perf.js`。
2. **断言有效性**：现有 5 处曾被变异测试揪出的"恒真断言"已修，但仍应把变异测试接入 `run-all`（现在需手动跑）。
3. **存档迁移**：`three_doors_*_v1` 键名已带版本，但 payload 无 `schemaVersion` → 加字段，未来改 schema 时做迁移而不是静默清空。
4. **代码分层**：`js/game.js` 已 1900+ 行，建议按"门/质疑/商店/成就/种子"拆成 5 个文件（只拆文件不改接口），利于多人并行。
5. **文档即契约**：`docs/设计契约_*.md` 已很好，建议把"验收命令 + 阈值"固化进 `run-all`（把 `--check`、mutation 纳入套件）。

## 6. 明确不建议做

- 联网排行榜 / 账号体系 / 皮肤付费（破坏"断网可跑"P0，且需后端）。
- 大改状态机或迁移表（收益低、回归风险高）。
- 引入构建链/框架（当前零构建是最大优势，双击即玩）。
- 为"更多门"而无限加门数（7–9 门会让屏幕信息密度失控、命中区变小；3–6 是最优区间）。
