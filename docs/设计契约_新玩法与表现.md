## 1. F1 线索契约（`js/narrator.js` + `js/game.js`）

### 1.1 数据结构

`GameData.narrator.lines[]` 每条可选新增字段：

```js
{
  id: 'lie_03', text: '……', kind: 'lie'|'lie_hard'|'truth',
  claimable: true,          // 可选，仅这三类可为 true
  claimType: 'slot_kind'|'big_prize_in'|'picked_kind'   // claimable 时必填
}
```

`Narrator.pickRoundLines(state, script)` 返回的每行可带：

```js
claim: {
  type: 'slot_kind', slot: 2, kind: 'empty', truthful: false
  // 或 type:'big_prize_in', slot: 1, truthful: false
  // 或 type:'picked_kind', kind: 'empty', truthful: true
}
```

**硬性约束**（qa 会逐条断言）：

1. `claim.truthful === (该陈述与实际 `state.doors` 相符)`，必须逐次计算，不得写死。
2. 引用了行文本的语义：`slot_kind` 文案必须含「N 号门」，`big_prize_in` 文案必须含「大奖」，`picked_kind` 文案必须含「你选/你手里」。
3. `kind === 'truth'` ⇒ `claim.truthful === true`；`kind === 'lie' | 'lie_hard'` ⇒ `claim.truthful === false`。
4. 只在 `claimable` 的行上生成 claim；未 claimable 的行保持旧逻辑（随机撒谎率）。
5. claim 涉及的 `slot` 必须是**决策时刻玩家仍不确定的门**（不得引用主持人已打开的 `opened` 门，否则玩家白拿答案）；`picked_kind` 只能断言玩家自己的门。
6. 生成必须走 `state.rng`（`RNG.pick`），同种子同操作可复现。

### 1.2 判定

```js
Narrator.resolveChallenge(state, line) -> {
  ok, coins, patience, suspicion, text, hint, claim
}
```

- `line.claim` 存在：`ok = !line.claim.truthful`（玩家识破了谎言才成功）；成功走 `suspicion.winCoins`，失败走 `loseCoins/losePatience`；`text` 用 `challenge_win`/`challenge_fail` 语料；`claim` 原样带回。
- 无 claim：保持旧路径（`lieRate` 随机）。
- 纯函数：只判定，不改 state。

### 1.3 引擎与 UI

- `js/game.js`：`challenge()` 已存在，只需把 `res.claim` 存进 `state.lastChallenge.claim`；连击奖励见 §2.1；toast 在成功时显示「识破 +N」。
- `js/ui.js`：旁白面板在文案下增加一行细字提示，内容取自 `state.lastChallenge.claim` 的人类可读摘要（`claimText(claim)`），仅当本轮已质疑过时显示；质疑按钮 `title` 改为「质疑 / 验证线索」。

## 2. F2 连击与怀疑值

### 2.1 连击奖励

`config.suspicion` 新增：`comboStep: 10, comboCap: 20`。
成功一次质疑的金币 = `winCoins + min(streakAfter - 1, 2) * comboStep`（即 20 / 30 / 40 封顶）。
`challengeStreak` 已有，失败清零。qa 断言：连续两次成功 = 20 然后 30。

### 2.2 怀疑值恢复与上限

- `config.suspicion.max = 3`（初始 2，可回补到 3）。
- `data/items.json`：`empty` 增加 `"suspicion": 1`；`small_prize` 增加 `"suspicion": 1`（描述文案同步改）。
- `js/effects.js` 的 `applyEffect`：怀疑值夹在 `0 .. config.suspicion.max`（拿不到 config 时上限 99，保持旧测试兼容）；金币仍 ≥0，耐心仍 0..∞ 且归零抛 `patience_zero`。
- HUD 无新 DOM，复用 `flash('suspicion')`。

### 4.2 判定规则（`js/game.js`，可被 qa 直接调用）

```js
Game.computeEndingId(state) -> 'all_in'|'comeback'|'iron_patience'|'master'|'pua'|'euro'|'anti'|'normal'
```

按 `priority` 从高到低取第一个满足条件的：

| id | 条件 |
|---|---|
| `all_in` | `state.challengesWon >= 3 && state.challengesLost === 0`（新字段，challenge() 里累加） |
| `comeback` | `state.minCoins <= 10 && state.coins >= 200`（新字段 `minCoins`，每次 `_apply` 后更新） |
| `iron_patience` | `state.coins != null && state.patience === config.initial.patience && state.round >= 3` |
| `master` | `state.round >= config.cashoutMaster.minRound && state.coins >= config.cashoutMaster.minCoins` |
| `pua` | `state.coins <= 99` |
| `euro` | `state.coins >= 200 && state.coins <= 299` |
| `anti` | `state.coins >= 300` |
| `normal` | 兜底 |

- 结算弹层（`_endingModal`）增加 `ending` 字段与「结局：<title>」行；`modalChoice('codex')` 不变。
- 结局同时写 `state.endingId`；`CodexStore.saveCodex({endings:{[id]:true}})`。

## 5. F5 提词器 / BGM / 光效

### 5.1 提词器

- 触发：`location.search` 含 `rehearsal=1` 或 `location.hash === '#rehearsal'`；`js/state.js` 的 `createInitialState` 从 init opts 接 `rehearsal`，存 `state.flags.rehearsal`（默认 false，不进 localStorage，重置后保持）。
- DOM（Lead 在 `index.html` 加，ui-render 只读不建）：
  ```html
  <section id="rehearsal" hidden aria-live="polite"><span id="rehearsal-text"></span></section>
  ```
- API（Lead 在 `js/game.js` 实现，ui-render 调用）：
  ```js
  Game.hintNextAction() -> { phase: string, text: string, choice: string|null }
  ```
  文案示例：PICK →「点任意一扇门」；DECIDE（有券）→「换门不花钱：有换门券」；DECIDE（演示第 2 轮）→「先点『质疑旁白』再点『收手/坚持』」；CASHOUT →「点『再来一局』或『结束』」。无提示时返回 `text:''`。
- `js/ui.js`：`state.flags.rehearsal` 为真时每次 `render` 更新 `#rehearsal-text` 并 `hidden=false`；不影响布局（`position:fixed` 右下、半透明、`pointer-events:none`、`z-index` 低于弹层）。

### 5.2 BGM

- `js/ui.js` 音效层新增 `bgm`：2 个 oscillator（低频 55–110Hz 正弦 + 轻微 detune），按 `state.round` 升调（第 1 轮 100Hz、第 3 轮 130Hz、≥4 轮 160Hz），gain ≤ 0.03。
- 停止条件：`state.flags.muted`、`phase === 'IDLE'`、`phase === 'GAME_OVER'`、页面 `visibilitychange` 隐藏时停；解锁手势后启动一次。
- 不得影响 `tests/dom-smoke.js`（Node 垫片无 AudioContext → 静默降级）。

### 5.3 开奖光效与金币飞入

- `playReveal`：给 `.door[data-slot]` 加 `.is-reveal-win`（金色光晕）/ `.is-reveal-lose`（红色抖动）class，`animation` 结束后移除；纯 CSS keyframes，≤600ms。
- 金币变化（`flash('coins', delta)` 且 `|delta| >= 10`）：从 `.door[data-slot].is-picked`（没有则从舞台中心）生成一个 `.coin-fly` 元素，`transform` 到 `#hud-coins` 位置，≤400ms 后 `remove()`；同时 HUD 数字跳动。
- 必须：不新增布局元素（绝对定位）、不触发滚动条、`prefers-reduced-motion` 下跳过动画（只保留最终数值）。

## 8. 定稿回写（实现中确认的细节，2026-10-25 凌晨）

1. **picked_kind 线索在质疑时刻补生成**：引擎是「先播旁白、后点门」，播报时玩家还没选门，所以 `picked_kind` 类 claim 由 `narrator.js` 在质疑调用时用同一份 `state` 补算，保证「你手里的是…」与真实门面一致；其余两类（`slot_kind` / `big_prize_in`）在 `pickRoundLines` 时就已算好。
2. **`iron_patience` 的判定基数是初始耐心**：`state.patience === config.initial.patience && round >= 3`。演示剧本三轮、耐心全程没掉，所以结算**结局是「稳如老狗」**，而称号仍是「欧皇候选」（250 金币）——称号看金币、结局看打法，两者不同源是预期行为。
3. **提词器是纯浮层**：`#rehearsal` 为 `position:fixed`（右下）、`pointer-events:none`、`z-index` 低于弹层；`ui.render()` 每次调用 `Game.hintNextAction()`（try/catch 兜底），不参与布局；重置/换局后随 `flags.rehearsal` 保持。
4. **BGM 实测**：2 个 sine、100/100.5Hz 起，第 1/3/≥4 轮 = 100/130/160Hz，增益 0.028（≤0.03），连续 render 不叠加；`muted` / `IDLE` / `GAME_OVER` / `document.hidden` 四条路径都压回 0.0001。
5. **测试收口**：`tests/run-all.js` 现为 **6 个套件**（`build-data --check` → `sim` → `shop` → `features` → `dom-smoke` → `headless`），基线 **415 PASS / 0 FAIL / 9 SKIP**；9 条 SKIP 全部来自 `headless-check.js`（本沙箱 Edge 必 EPERM），由 dom-smoke 98 项 + sim G7.6/G7.7 交叉覆盖。`STRICT=1` 因此 exit=1，属预期口径。
6. **连击口径**：`Game.challenge()` 的返回值表示「质疑被受理」，真假看 `state.lastChallenge.ok`；连击金币 = `winCoins + min(streak-1, 2) * comboStep`（20 → 30 → 40 封顶），失败清零并把 `grudge +1`。
