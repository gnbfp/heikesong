## 2. 引擎已就绪的能力（v5 由 Lead 实现，A/B/C 直接消费，不要重写）

### 2.1 多门（3–6 扇 / 每轮）
- `state.doorCount`（number，3–6）：本轮门数；每轮在 `beginRound()` 里确定一次。
- `state.doors`：长度 = `state.doorCount`，元素 `{ slot, itemId, opened, revealed }`（`slot` 从 0 连续编号）。
- `Game.doorCountFor(round)`：本轮门数决策。优先级：**演示剧本 doors 长度** → 普通模式 `?doors=N` → `config.doorCount` 权重抽 → 缺配置时 3。
- `Game.generateDoors(round)`：发牌。4–6 门的回合**保证恰好 1 扇 `big_prize`**；3 门保持旧行为（≤1 个）。
- `Game.hostPick(doors, pickedSlot)`：主持人开门规则（冻结）——不开玩家所选、不开大奖，优先空门，返回槽位。
- `Game.chooseDoor(slot)` 会调用 `hostPick` 并只开 **1 扇**门 → 进入 DECIDE。
- `Game.switchDoor()`：换到「第一扇未开、未揭示、且不是当前所选」的门；有换门券消耗券，否则花 `economy.switchCost` 金币，都没有则拒绝。
- `?doors=N`（N 取 3–6）：普通模式下强制门数，用于演示与回归；**演示模式（剧本）始终按剧本的 doors 长度**。
- 键盘 `1`–`6`：引擎只要求 UI 发出 `{type:'pick', slot}`；当前 UI 只映射了 1–3，**扩展到 1–6 是工作流 A 的任务**。

### 2.2 `config.doorCount` 数据格式（工作流 B 新增，缺省时引擎按 3 门跑）
```json
"doorCount": { "min": 3, "max": 6, "weights": { "3": 45, "4": 30, "5": 18, "6": 7 } }
```
- `weights` 的键必须落在 `[min,max]` 且是 3–6 的整数；权重非负、总和 > 0；引擎用 `state.rng` 抽，因此**同一种子可复现**。

### 2.3 既有 DOM（A 只可读、不可改结构，新增元素由 Lead 决定）
`#round-chip`（轮次）、`#doors-count`（本轮门数徽标，Lead 已加）、`#mode-chip`、`#controls`（`#btn-reset/#btn-demo/#btn-shop/#btn-mute/#btn-skip/#btn-help/#btn-settings`）、`#stage`、`#doors[data-cols]`、`#round-banner`、`#hud`、`#narrator`、`#decide`（5 个 `[data-choice]`）、`#hint`、`#toast`、`#modal`、`#shop`、`#bag`、`#tutorial`、`#rehearsal`、`#confetti`、`#portrait-hint`。
